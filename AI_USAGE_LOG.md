# AI Usage Log

## Introduction

This document records the use of artificial intelligence tools during the development of the StudyHub-IL project. Each team is required to document 3-5 significant cases where AI tools were used as part of the course requirements.

**Important Note**: Using AI did not always yield a perfect solution on the first try. In most cases, we had to write multiple prompts, check the results, manually fix issues, and deeply understand the generated code before integrating it into the project.

## Principles of AI Usage in the Project

- **Full Control**: Students maintain complete control and understanding of all AI-generated outputs
- **Iterative Process**: Every AI usage required multiple attempts and manual interventions
- **Rigorous Review**: All code generated by AI underwent thorough review, correction, and improvement
- **Self-Learning**: AI usage served as a learning tool, but required significant investment in understanding

## Case 1: Fixing Login Error - Missing Database Columns

### Problem/Task
Users received an error when logging into the system:
```
PrismaClientKnownRequestError: Invalid `prisma.user.findUnique()` invocation
The column `users.bio` does not exist in the current database.
```

The Prisma schema (`schema.prisma`) included additional profile fields (`bio`, `location`, `institution`, `fieldOfStudy`, `website`, `interests`) but the PostgreSQL database was not updated with these columns.

### AI Tool Used
- **GitHub Copilot** - for assistance writing migration code
- **ChatGPT-4** - for understanding Prisma migrations and problem-solving

### Main Prompts (and subsequent iterations)

**First Prompt** (didn't work as expected):
```
"I'm getting an error about missing column users.bio in PostgreSQL. How do I fix it?"
```

**Result**: The answer was too generic and didn't help solve the specific problem.

**Second Prompt** (better but still not perfect):
```
"My Prisma schema has been updated with new fields but the database wasn't synced. 
What's the safest way to sync the database schema without losing data?"
```

**Result**: Got basic instructions about `prisma migrate dev` but it didn't work in our environment.

**Third Prompt** (after experimentation):
```
"I have a Prisma schema with new fields: bio, location, institution, fieldOfStudy, website, interests 
in User model. I need to:
1. Create a migration file that adds these columns safely
2. Make it idempotent (can run multiple times)
3. Create scripts for both Linux and Windows
4. Handle the case where columns might already exist

Database: PostgreSQL
Fields should be nullable except interests which defaults to empty array
"
```

### What Actually Happened - The Real Process

1. **First Attempt**: AI suggested `prisma migrate dev` but it created a non-idempotent migration
2. **Manual Fix #1**: We added `IF NOT EXISTS` to the SQL ourselves
3. **Second Attempt**: Tried to run the migration but encountered permission issues
4. **Manual Fix #2**: Fixed database permissions
5. **Third Attempt**: Migration ran but Prisma client wasn't updated
6. **Manual Fix #3**: Manually ran `npx prisma generate`
7. **Script Creation**: Wrote `sync-database.sh` and `sync-database.bat` ourselves
8. **Documentation**: Wrote `DATABASE_MIGRATION.md` so others wouldn't get stuck on the same issue

### How AI Advanced the Project (Despite Challenges)

- **Initial Direction**: AI helped understand we needed to use Prisma migrations
- **Code Examples**: Got SQL examples to build upon
- **Learning**: Learned about Prisma migration system through AI explanations
- **Time Saved**: Despite challenges, saved time compared to learning everything from scratch

**Time Investment**: About 4-5 hours including debugging and experimentation, instead of a full day doing everything alone

**Files Created/Modified**:
- `server/prisma/migrations/20231207000000_add_user_profile_fields/migration.sql`
- `server/prisma/migrations/migration_lock.toml`
- `sync-database.sh` (mostly written manually)
- `sync-database.bat` (mostly written manually)
- `DATABASE_MIGRATION.md`
- `.gitignore` (update)
- `README.md` (added instructions)

## Case 3: Profile Picture Upload Security

### Problem/Task

Implemented profile picture upload feature to Azure Blob Storage. When running security check (CodeQL), received two critical alerts:
1. **URL Validation Bypass** - URL validation using `string.includes()` can be bypassed
2. **Missing Rate Limiting** - No rate limiting on upload endpoint

### AI Tool Used
- **GitHub Copilot** - for assistance writing security code
- **ChatGPT** - for understanding security vulnerabilities and solutions

### The Real Process

**First Prompt** (too generic):
```
"How do I validate Azure Blob Storage URLs?"
```
**Result**: Suggested using regex, which wasn't good enough.

**Second Prompt** (after understanding the issue):
```
"CodeQL found vulnerability: URL validation using string contains could be bypassed. 
Current code checks if URL includes '.blob.core.windows.net'. 
What's the secure way to validate Azure Blob Storage URLs?"
```
**Result**: Suggested using URL parser, but provided code wasn't complete.

**What We Actually Did**:

1. **First Attempt**: Used AI-provided code - didn't work, got errors
2. **Manual Fix**: Added try-catch and understood we need to check both protocol and hostname
3. **Second Attempt**: Wrote the full logic ourselves:
   ```javascript
   const parsedUrl = new URL(url);
   if (parsedUrl.protocol !== 'https:') return false;
   if (!parsedUrl.hostname.endsWith('.blob.core.windows.net')) return false;
   if (!parsedUrl.pathname.startsWith('/avatars/')) return false;
   ```
4. **Testing**: Wrote test cases to verify validation works
5. **Rate limiting**: Asked AI about express-rate-limit but got unsuitable configuration
6. **Manual Fix**: Adapted configuration to our needs (5 uploads per 15 minutes)

**Additional Prompts**: At least 4-5 prompts about rate limiting, MIME types, and file extension validation

### How AI Advanced the Project

- **Problem Awareness**: AI helped understand what the vulnerabilities are
- **Solution Direction**: Pointed to using URL parser and rate limiting
- **Examples**: Got initial examples to build upon
- **Learning**: Learned about web application security

**Time Investment**: 5-6 hours on security, instead of a week of independent research

**Files Created/Modified**:
- `server/src/routes/auth.js` (security fixes)
- `server/src/lib/azureStorage.js` (improved URL validation)
- `AVATAR_UPLOAD_SECURITY.md` (comprehensive documentation)

## Summary and Lessons Learned

### The Reality of Working with AI

**What Worked Well**:
- Getting initial structure and direction
- Code examples for new technologies
- Explanations of unfamiliar concepts
- Time savings on boilerplate code
- Help with documentation

**What Didn't Work as Expected**:
- Original code almost never worked "out of the box"
- We had to deeply understand every piece of code
- Manual fixes were almost always necessary
- Integration with existing code required significant work
- AI didn't always understand the full project context

### Real Statistics

- **Average prompts per feature**: 5-10 prompts
- **Percentage of manually written code**: About 60-70%
- **Debugging time**: 2-3x the writing time
- **Overall time savings**: About 30-40% compared to writing from scratch

### Principles We Learned

1. **AI is a tool, not a replacement**: Must understand everything it generates
2. **Prompt engineering matters**: More specific prompt = better result
3. **Iterative process**: Check, fix, improve - that's the real process
4. **Project context**: AI doesn't know existing code, must provide context
5. **Always validate**: Security check, code review, logic check - mandatory

### Continued Usage

We continue to use AI in the project, but with realistic expectations:
- Source for ideas and direction
- Help learning technologies
- Time savings on repetitive tasks
- **But always with review, understanding, and fixes**
